# Durable decisions

| Date | Decision | Reason |
| --- | --- | --- |
| 2026-08-12 | Create Source/SprayerDesktop and Source/SprayerController as verified copies, not links or in-place edits. | Both original projects are immutable comparison baselines. |
| 2026-08-12 | Exclude only generated directories named bin, obj, build, cmake-build-*, .git, and .vs during copying. | Retains all source, tests, CubeMX, tools, README, IDE and toolchain definitions needed to reproduce the baseline. |
| 2026-08-12 | Track SHA-256 manifests for included baseline files. | Provides a repeatable proof that copied source is exactly the pre-copy baseline and that copying did not alter it. |
| 2026-08-12 | Keep source and toolchain-sensitive paths English ASCII. | Avoids toolchain and migration path issues; explanatory documentation may remain Chinese. |
| 2026-08-12 | Keep the desktop on .NET 8 WPF and evolve protocol behavior incrementally behind tested layers. | The working Modbus, discovery and reconnect behavior is a valuable baseline; an unrelated framework rewrite is out of scope. |
| 2026-08-12 | Use an explicit eight-bit nozzle mask for protocol v2, with controller readback authoritative. | Individual nozzles, side masters, presets and custom patterns require one unambiguous confirmed state. |
| 2026-08-12 | Store calibration, PWM lower bound and safety minimum locally with atomic persistence. | The ten-point calibration is host configuration, not STM32 Flash data. |
| 2026-08-12 | Fix PWM upper limit at 80 percent pending thermal validation. | Hardware safety evidence is required before changing that limit. |
| 2026-08-12 | Allocate protocol-v2 holding register 0x000C and capabilities 0x010A..0x010B. | Explicit eight-nozzle commands and version/feature negotiation must be unambiguous while retaining legacy modes. |
| 2026-08-12 | Use Flash schema v4 while decoding schema v3. | The existing 24-byte record retains its layout and CRC coverage; reserved byte 19 now persists the effective nozzle mask. |
| 2026-08-12 | Detect protocol-v2 desktop support by capability registers, with illegal-address-only legacy fallback. | A legacy device returns Modbus exception `0x02` as a valid five-byte frame; treating any communication fault as legacy would hide real connection/protocol errors. |
| 2026-08-12 | Add a disposable controller-session boundary without a second retry policy. | Application code can use hardware and demo sessions consistently while existing serial/retry/discovery layers retain transport ownership. |
| 2026-08-12 | Persist only schema-1 host calibration/settings through a same-directory temporary file and atomic replace/move. | A validated document can be recovered independently of the controller, while a failed/cancelled save preserves the prior valid bytes. |
| 2026-08-12 | Keep interaction state as preview, pending, and controller-confirmed ViewModel state behind one gate per controller session. | UI drag/preview must not transmit, and equipment writes must not race or become authoritative before controller readback. |
| 2026-08-12 | Keep the production shell borderless/maximized and make demo, windowed dimensions, and capture explicit startup options. | Cab touch operation remains the safe default while repeatable non-hardware review does not alter production behavior. |
| 2026-08-12 | Treat the approved reference image as the visual baseline while retaining native responsive WPF controls. | The product must reproduce its dark palette, compact 40/24/36 layout, circular nozzles, canopy ladder, horseshoe gauges and connection/readback/log hierarchy without using a bitmap background. |
| 2026-08-12 | Hard-block demo persistence and require a separate second confirmation for real controller power-on defaults. | Review data must never become product configuration, and controller Flash changes must be explicit and use the tested custom-settings, explicit-mask and save-key sequence. |
| 2026-08-12 | Release desktop and firmware together as version 1.0.0 with project-relative SHA-256 checksums. | The host implementation, explicit-mask firmware and compatibility expectations are a single tested contract; checksum entries make copied delivery artifacts auditable. |
| 2026-08-12 | Keep release delivery framework-dependent for `win-x64`. | The intended Windows touchscreen deployment provides the .NET 8 runtime; this keeps the package compact while retaining a reproducible `dotnet publish` command. |
| 2026-08-12 | Render the eight nozzle rings as pure status indicators that are never focusable/hit-testable, and move canopy presets to a four-position vertical snapping slider. | The delivered behavior never exposed individual nozzle touch control; the rings now truthfully show controller-confirmed or preview state, and the slider drag previews while a single mouse/touch release commits one preset. |
| 2026-08-12 | Keep `DashboardViewModel.ToggleNozzleAsync` as a protocol/test capability while the UI no longer binds individual nozzle commands. | Removes misleading dashboard interaction without deleting a tested write path; real entries remain left/right masters, canopy slider, PWM master and duty gauges. |
